# 설계: 하네스를 모드 런타임으로 (초안, 2026-10-15)

## 왜

harnist 의 목표는 "세션마다, 특히 경량 서브에이전트마다 필요한 것만 싣기"다. 지금은 모듈을 `.claude/` 파일로 생성해서 레포 단위까지만 고를 수 있고, 생성물은 그 레포의 모든 세션·모든 서브에이전트에 똑같이 실린다. 스폰 규칙은 CLAUDE.md 문장이라 강제되지 않는다.

Claude Code 모드(v2.1.287+)는 세션 안에서 이벤트를 가로채 시스템 프롬프트 섹션, 주입 메시지, 도구 설명, 서브에이전트 생성, 권한 판정을 바꿀 수 있다. 이걸 쓰면 "무엇을 싣는가"를 레포가 아니라 **세션·에이전트 역할** 단위로 정하고, 규칙을 문장이 아니라 코드로 강제할 수 있다.

## 제약 — 모드는 세션 시작 때 한 번 로드된다

세션 도중에 다른 플러그인을 새로 켤 수 없고, 같은 세션의 서브에이전트는 부모와 같은 모드 집합을 쓴다. 그래서 "스폰할 때 모드 조합을 로딩"은 두 갈래다.

| 경우 | 방법 |
| --- | --- |
| 별도 프로세스(`claude -p` 일꾼, crew 작업자) | 실행 인자(`--plugin-dir`, `--settings`)로 조합을 골라 띄운다. child profile 이 컴파일한다 |
| 같은 세션의 서브에이전트 | 이미 로드된 **런타임 모드 하나**가 에이전트별로 동작을 바꾼다 |

## 구조 — 모듈은 데이터, 모드는 런타임 하나

- **모듈 = 선언 데이터.** 규칙(프롬프트 조각), 스폰 규칙(동시 수·모델), 가드(도구·경로·명령), 역할별 도구 목록. 모듈마다 모드를 하나씩 만들지 않는다(디버깅·버전·로딩 순서가 감당 안 된다).
- **harnist-runtime 모드.** 항상 로드되어 레포의 `harness.yaml` 이 고른 모듈 데이터를 읽고 에이전트별로 적용한다.
  - `agent.spawn` — 모델 지정, 동시 수 상한, 금지 역할 거부
  - `prompt.compose` / `prompt.section` — 그 역할에 필요한 규칙만 시스템 프롬프트에
  - `tool.check` / `tool.describe` / `agent.offer` — 역할별 도구·에이전트 목록 거르기
  - `prompt.attachment` — 스킬 목록 주입을 역할별로 줄이기 (원래 문제: 200k 서브에이전트의 스킬 목록 예산 초과)
- **코드 모드.** lens(관측), loop(루프·큐) 처럼 고유 동작이 있는 것만 별도 모드로 두고, 런타임이 데이터로 켠다.
- **그대로 두는 것.** 스킬(필요할 때만 읽힘)과 MCP(외부 연결)는 모드로 옮겨도 이득이 없다.
- **대체 경로.** 조직 관리 환경(프롬프트 계열 이벤트가 사용자 플러그인에 안 옴), VS Code 등 화면이 없는 곳을 위해 지금의 `.claude/` 생성 경로를 남긴다.

## 검증

lens 가 기본 로드 토큰·캐시 히트·턴 점수를 세션마다 기록한다. 같은 레포에서 모드화 전후를 비교하고, lens 의 프롬프트 A/B 실험으로 "규칙을 CLAUDE.md 로 늘 실을 때 vs 런타임이 역할별로 넣을 때"를 세션마다 갈라 비교한다.

## 순서

1. **탐침** — 서브에이전트에 대해 어떤 이벤트가 따로 오는지(시스템 프롬프트 섹션, 스킬 목록 주입, 도구 설명, 에이전트 목록), 각 이벤트가 `agentId` 로 구분되는지 실측한다. 이 결과가 런타임이 할 수 있는 범위를 정한다.
2. **런타임 최소판** — 스폰 규칙 강제와 역할별 규칙 주입.
3. **lens 로 측정** — 전후 비교, A/B.
4. **프로세스 단위 조합** — child profile 에 모드 조합을 얹어 별도 프로세스 일꾼을 목적별로 띄운다.

## 탐침 1 결과 (2026-10-15, Claude Code 2.1.300)

`cc-mods/subagent-probe` 로 sonnet 메인 세션이 Explore(라우터가 haiku 로 보냄)·general-purpose 서브에이전트를 차례로 띄우게 하고 이벤트를 기록했다.

| 이벤트 | 서브에이전트에 따로 오나 | 구분 |
| --- | --- | --- |
| `prompt.compose`, `prompt.section` | **오지 않는다.** 메인 세션에서만 발생 | — |
| `prompt.attachment` | **온다.** 요청마다, 서브에이전트별로 | `agentId` |
| `agent.spawn` | 온다 | 결과에 `agentId` → 종류와 짝지을 수 있다 |
| `turn.start`, `turn.step`, `tool.call` | 온다 | `agentId` |
| `agent.offer`, `tool.describe` | 요청마다 오지만 | `agentId` 없음 → 에이전트별로 거를 수 없다 |

서브에이전트마다 실리는 주입(첫 요청 기준): 스킬 목록 6,931자, MCP 서버 안내 5,949자, CLAUDE.md 5,269자(general-purpose 만, Explore 는 안 받음), 도구 목록·에이전트 목록.

**쓰기 시험**: 서브에이전트의 `skill_listing` 주입만 한 줄로 바꿨더니 서브에이전트는 바뀐 목록만 봤고 메인은 원래 목록 그대로였다. → 런타임은 `agent.spawn` 으로 `agentId → 역할` 을 잡고, `prompt.attachment` 로 그 역할에 맞게 스킬 목록·MCP 안내·CLAUDE.md 를 깎을 수 있다. harnist 의 원래 문제(경량 서브에이전트의 스킬 목록 예산 초과)를 정면으로 푸는 경로다.

**설계에 미치는 영향**
- 서브에이전트 역할별 규칙은 시스템 프롬프트 섹션이 아니라 **주입 메시지 편집**과, 역할 에이전트를 `$.agent.register` 로 정의할 때의 프롬프트로 넣는다.
- 역할별 도구 제한은 설명을 숨기는 대신 `tool.check` 거부로 한다.

## 런타임 최소판 (runtime 0.1.0)

`runtime/` 플러그인. 설정은 레포의 `.claude/harnist-runtime.json`, 없으면 `~/.claude/harnist-runtime.json` (예시: `runtime/examples/harnist-runtime.json`). 역할 키는 서브에이전트 종류, `*` 는 기본값. 메인 세션은 건드리지 않는다.

- `agent.spawn` — 금지 종류 거부, 동시 실행 상한(`$.agent.list()` 의 pending·running·waiting), 역할 모델 지정(Claude 가 고른 모델은 둔다). 결과의 `agentId` 로 역할을 기억한다
- `prompt.attachment` — `skill_listing`(항목 단위), `mcp_instructions_delta`(`## 서버` 절 단위), `deferred_tools_delta`(`mcp__서버__` 줄), `instructions`(`Contents of <경로>` 블록 단위)를 역할대로 거른다. 남는 게 없으면 `null` 로 주입째 뺀다
- `tool.check` — 역할의 `denyTools` 와 열지 않은 MCP 서버 도구를 거부
- `/runtime` — 적용 중인 규칙과 이 세션에서 깎은 글자 수, `/runtime reload`

**실세션 확인** (sonnet 메인, 임시 레포): Explore 는 스킬·MCP 안내·CLAUDE.md 를 하나도 받지 않았고 Bash 가 런타임 사유로 거부됐다. general-purpose 는 허용한 스킬 6개(loop, memory-bank:*)·askew 안내·레포 CLAUDE.md 만 받았고 Bash 는 그대로 됐다. Plan 생성은 런타임 사유로 거부됐다.

**한계**: 처음부터 로드된(지연이 아닌) 도구의 스키마는 `tool.describe` 에 `agentId` 가 없어 숨길 수 없다 — 시험에서 Explore 도 Claude Docs 도구 3개를 봤다. 호출은 `tool.check` 가 막는다. 사용자 범위 router 모드와 모델 지정이 겹치면 먼저 도는 쪽이 정한다.

## 측정 (2026-10-15, lens)

harnist 레포, sonnet 메인이 Explore(haiku)·general-purpose 를 하나씩 띄우는 같은 지시. B 의 설정은 두 역할 모두 스킬·MCP 를 빼고, CLAUDE.md 는 Explore 는 빼고 general-purpose 는 레포 것만 남겼다. 세 번 모두 답은 같았다.

| 실행 | 메인 첫 요청 | Explore 첫 요청 | general-purpose 첫 요청 | 비용 |
| --- | --- | --- | --- | --- |
| A 런타임 없음 (캐시 없음) | 27,341 | 13,128 | 18,959 | $0.186 |
| B 런타임 | 27,343 | **9,413 (−28%)** | **12,400 (−35%)** | $0.081 |
| A2 런타임 없음 (캐시 데워짐) | 27,341 | 13,128 | 18,959 | $0.025 |

- 서브에이전트의 첫 요청 토큰은 캐시와 무관하게 28–35% 줄었다. 서브에이전트의 컨텍스트 여유와, 캐시가 차가울 때의 쓰기 비용이 이득이다.
- **비용은 캐시 상태가 지배한다.** 같은 서브에이전트를 자주 띄우면 깎지 않은 앞부분도 캐시 읽기(10% 가격)로 싸게 재사용된다. B 는 앞부분이 바뀌어 처음 한 번 캐시를 새로 썼다. 그래서 "역할 설정을 자주 바꾸지 않는다"가 운영 규칙이 된다 — 바꿀 때마다 그 역할의 캐시가 한 번 깨진다.
- lens 의 `attachment` 기록에는 `agentId` 가 없어 서브에이전트별 주입 글자 수는 lens 로 못 본다. lens 에 `agentId` 를 붙이는 것이 다음 할 일이다.

## 운영 규칙

- **역할 규칙은 자주 바꾸지 않는다.** 바꿀 때마다 그 역할의 첫 요청 앞부분이 달라져 캐시를 한 번 새로 쓴다. 레포마다 한 번 정하고 둔다.
- **메인 세션은 건드리지 않는다.** 런타임은 서브에이전트에만 작용하므로 메인의 캐시는 설정과 무관하게 안정적이다.
- **고친 뒤 `/runtime` 으로 확인하고 `/runtime reload`.** 깨진 파일은 반쯤 적용되지 않고 런타임을 끈다.
- **별도 프로세스 일꾼은 자기 파일을 받는다.** `HARNIST_RUNTIME_CONFIG` 가 레포 파일보다 우선한다.
- **필요한 것부터 적고 나머지를 뺀다.** 뺀 스킬·규칙은 그 역할이 "모른다"고 답한다(손해 평가: 해당 과제 5/5 실패, 지어낸 답 0). 목록에서 뺀 스킬도 이름을 주면 불러올 수 있으니, 꼭 막아야 할 때만 `denyTools: ["Skill"]`.

## 4. 프로세스 단위 조합 (2026-10-15)

`profiles.<이름>` 에 `mods`(플러그인 폴더, `lens`·`runtime` 은 이름만), `runtime`(역할 설정 JSON 경로) 키를 더했다. claude 로 컴파일하면 `--plugin-dir` 와 `HARNIST_RUNTIME_CONFIG` 가 된다. 도구 목록에 `agent` 를 추가했다 — 없으면 일꾼이 서브에이전트를 못 띄워 runtime 이 무력하므로 compile 이 경고한다. Codex 는 모드가 없어 강제 불가.

실측: `scout` 프로필(읽기 전용, `inherit: project`, `tools: [read, search, agent]`, `mods: [lens, runtime]`, Explore 는 스킬·MCP·CLAUDE.md 를 뺌)을 컴파일해 띄웠다. 사용자 플러그인이 끊긴 채 lens·runtime 만 실렸고, Explore 는 스킬 0개·CLAUDE.md 없음으로 동작했다. lens 는 주입 기록에 `agentId` 를 남기도록 고쳐(0.5.1), 이 실행에서 메인 6,446자·Explore 1,385자로 갈라 보였다. 집계(lens·harnist)는 훅 주입을 메인 기준으로만 센다.

## 효과 평가 (2026-10-15, `runtime/eval/run.py`)

harnist 탐침처럼 자기보고 없이 증거로 판정한다. 같은 과제를 런타임 없이(A)·켜고(B) 번갈아 3번씩, sonnet 메인으로 harnist 레포에서 돌렸다. 과제는 서브에이전트 7개(Explore 3·general-purpose 3·Plan 1)이고 정답은 스크립트가 레포에서 계산한다. 증거는 stream-json 트레이스와 lens 기록(서브에이전트별 주입·첫 요청·생성 거부)이다. 설정은 Explore 가 스킬·MCP·CLAUDE.md 없음 + Bash 금지, general-purpose 가 `memory-bank:*` 스킬·레포 CLAUDE.md 만, Plan 생성 금지.

| 지표 (3회 평균) | A | B |
| --- | --- | --- |
| 메인 첫 요청 | 27,916 | 27,916 |
| Explore 첫 요청 | 13,142 | **9,427 (−28%)** |
| general-purpose 첫 요청 | 19,016 | **12,859 (−32%)** |
| general-purpose 스킬 목록 / CLAUDE.md (자) | 6,931 / 5,269 | 1,129 / 832 |
| Plan 첫 요청 | 13,245 | 0 (거부) |
| 실행당 비용 | $0.157 | $0.105 |
| 실행당 시간 | 54s | 51s |
| 정답 (과제 5개 × 3회) | 15/15 | 15/15 |
| Explore Bash 런타임 거부 | 0/3 | 3/3 |
| Plan 생성 런타임 거부 | 0/3 | 3/3 |

- **정확도 손실 없음.** 깎은 뒤에도 과제 5개를 모두 맞혔다. 허용한 스킬(`memory-bank:search-conversations`)과 레포 규칙(테스트 명령)은 남아서 필요한 답을 냈다.
- **강제는 3/3.** Bash·Plan 거부는 트레이스의 런타임 사유 문자열로 확인했다.
- **비용은 신중히 읽는다.** 실행마다 캐시 상태가 달라 편차가 크다(A $0.085–0.235, B $0.072–0.147). 가장 데워진 3회차끼리는 $0.085 → $0.072 (−15%)이고, 이 차이에는 거부된 Plan 한 번(13k 토큰)이 섞여 있다. 확실한 이득은 서브에이전트 컨텍스트 28–32% 감소다.
- **이 평가가 못 보인 것.** s4(Explore 에게 레포 규칙 묻기)는 트레이드오프를 보이려던 과제였는데, Explore 는 원래도 CLAUDE.md 를 받지 않고 파일을 직접 읽어 맞혔다. 깎은 맥락 때문에 틀리는 경우는 이 과제 묶음에서 나오지 않았다 — 스킬을 빼 버린 역할에 그 스킬이 필요한 일을 맡기는 과제를 더하는 것이 다음 평가 거리다.
- **평가 중 고친 것.** 런타임이 깎은 주입을 아래 플러그인에 넘기지 않아 lens 가 못 보던 문제(runtime 0.2.0), lens 가 들어온 텍스트가 아니라 모델이 읽는 최종 텍스트를 세도록(lens 0.5.1), 생성 기록에 `agentId`·거부 사유를 남기도록 했다. `profile probe` 는 프로필이 실은 모드·그 모드의 도구·`Task`(Agent 의 옛 이름)를 상속·넘친 도구로 오판하던 것을 고쳤다.

**동시 실행 5+5** (`--reps 5 --parallel`, 10개 세션을 한꺼번에 띄워 두 조건이 같은 시간대·캐시 상황을 겪게 함, 13:24–13:25): 토큰은 순차 평가와 같았다(Explore 13,141 → 9,426, general-purpose 18,964 → 12,807, 메인 동일). 정답 25/25 대 25/25, Bash·Plan 거부 5/5. 비용은 A $0.188 (중앙값 $0.203, 표준편차 $0.052) → B $0.139 (중앙값 $0.140, 표준편차 $0.010)으로 평균 −26%이고, B 쪽 편차가 훨씬 작다. 앞부분이 작아 캐시를 덜 쓰고 덜 읽기 때문으로 보인다. 이 차이에도 거부된 Plan 한 번이 섞여 있다. 시간은 64s → 59s.

### 손해 평가 (`--suite loss --reps 5 --parallel`, 13:27)

B 설정이 깎는 것을 일부러 필요하게 만든 과제 다섯 개. 정답 판정은 답의 내용으로만 한다.

| 과제 | 깎인 것 | A | B |
| --- | --- | --- | --- |
| l1 Explore: 지난 대화 검색 스킬 이름 | Explore 스킬 목록 전부 | 5/5 | **0/5** (NONE) |
| l2 general-purpose: 전역 CLAUDE.md 의 "응답당 질문 수" | 전역 CLAUDE.md (레포 것만 남김) | 5/5 | **0/5** (UNKNOWN) |
| l3 general-purpose: 아이폰 단축어 MCP 서버 이름 (재설계 후) | MCP 안내 | 5/5 | **0/5** (NONE) |
| l4 general-purpose: .xlsx 스킬 이름 | `memory-bank:*` 밖 스킬 | 5/5 | **0/5** (NONE) |
| l5 general-purpose: 이름을 주고 Skill 도구로 xlsx 불러오기 | (목록에서만 빠짐) | 5/5 | **5/5** |

- **손해는 실재하고 예측대로다.** 깎은 정보가 필요한 과제는 B 에서 5/5 실패했다. 실패는 모두 NONE·UNKNOWN 으로 "모른다"고 답한 것이고, 그럴듯한 오답을 지어낸 경우는 없었다. 즉 런타임의 손해는 조용한 오답이 아니라 드러나는 공백이다.
- **목록에서 빼는 것은 숨기기일 뿐 막기가 아니다.** l5: 스킬 목록에 없어도 이름을 알면 Skill 도구로 그대로 불러온다. 역할에 꼭 필요한 스킬은 (1) `skills` 에 남기거나 (2) 서브에이전트에게 주는 프롬프트에 이름을 적으면 된다. 반대로 정말 막아야 하면 `denyTools` 에 `Skill` 을 넣는다.
- **l3 은 처음 설계가 무효였다.** 첫 실행에서는 A 도 5/5 NONE 이었다. 탐침으로 원인을 찾았다: **서브에이전트는 MCP 서버 안내를 첫 요청이 아니라 두 번째 요청부터 받는다**(도구를 한 번 쓴 뒤 `mcp_instructions_delta` 로 들어온다, 메인은 첫 요청에 받는다). 도구 없이 바로 답하는 과제에는 안내가 아예 실리지 않는다. "먼저 Glob 을 한 번 쓰고 답하라"로 고친 재실행(13:56)에서 A 5/5(askew), B 0/5. 앞선 평균들에서 서브에이전트 MCP 안내가 1,487·1,983자처럼 들쭉날쭉했던 것도, 여러 번 요청한 과제만 5,949자를 받았기 때문이다.
- **Plan 거부가 섞이지 않은 비용 비교.** 이 묶음에는 Plan 이 없어 깎기 효과만 남는다: 실행당 $0.234 → $0.179 (−24%), 시간 49s → 47s, 서브에이전트 첫 요청 −28%(Explore)·−32%(general-purpose). 재실행에서는 $0.151 → $0.137 (−9%)로 차이가 작았다 — 손해 묶음의 비용 절감은 9~24% 사이에서 흔들리고, 확실한 것은 첫 요청 토큰 감소다.

**운영 규칙에 더할 것**: 역할 규칙을 정할 때는 "그 역할이 맡을 일에 필요한 스킬·전역 규칙"을 먼저 적고 나머지를 뺀다. 빼는 순간 그 역할은 해당 정보를 모른다고 답한다(지어내지는 않는다). 전역 CLAUDE.md 의 말투·질문 수 같은 규칙은 결과물을 사람에게 직접 보여주는 역할에만 필요하다.

재현: `python3 runtime/eval/run.py --reps 3` (원본은 `~/.cache/harnist-runtime-eval/`).

## 실제 적용 (2026-10-15)

**전역** — `manifests/global/harness.yaml` 에 조사·안내 역할만 깎는 `roles:`(Explore·claude-code-guide·statusline-setup 의 스킬 목록·MCP·CLAUDE.md)를 두고 `~/.claude/harnist-runtime.json` 을 생성, `runtime@harnist` 를 사용자 범위에 설치했다. 레포 설정이 없는 폴더의 새 세션에서 Explore 의 스킬 목록·MCP 안내가 0자, 지연 도구 목록이 2,116 → 461자.

**readlate (개인 앱 레포)** — 레포 전용 모듈이 자기 에이전트에 필요한 것을 선언했다(ops-reporter 는 ops 스킬 2개, 스크린샷 팀은 역할별 스킬, 모두 MCP 없음·이 레포 CLAUDE.md/AGENTS.md 만). 같은 지시(세 역할을 띄워 Glob 한 번 후 스킬 이름 답하기)로 적용 전후를 쟀다.

| 역할 | 적용 전 첫 요청 | 적용 후 | 스킬 목록 (자) | CLAUDE.md (자) | MCP 안내 (자) |
| --- | --- | --- | --- | --- | --- |
| screenshot-compositor | 23,849 | **15,780 (−34%)** | 8,573 → 0 | 8,717 → 4,208 | 5,949 → 0 |
| ops-reporter | 23,117 | **15,554 (−33%)** | 8,573 → 637 | 8,717 → 4,208 | 5,949 → 0 |
| Explore (전역 규칙이 이미 적용) | 9,427 | 9,426 | 0 → 0 | 0 → 0 | 0 → 0 |

ops-reporter 는 적용 후 자기 스킬 두 개(`asc-ops-report, aso-rank-watch`)만 답했다. **측정이 드러낸 기존 빈틈**: compositor 가 배경 생성에 써야 할 `image-gen` 은 적용 전에도 목록에 없었다 — 10-06 전역 점검 때 레지스트리로 보관돼 모델이 부를 수 없는 스텁이 됐기 때문이다(에이전트 정의는 옛 이름 `gpt-image-gen` 을 가리킨다). 역할 선언이 "이 역할에 무엇이 필요한가"를 적게 하면서, 필요한데 실리지 않는 것이 보이게 됐다. 해결은 readlate 에 `domain/image-gen` 모듈을 연결하는 것.
