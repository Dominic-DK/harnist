# 설계: 하네스를 모드 런타임으로 (초안, 2026-10-15)

## 왜

harnist 의 목표는 "세션마다, 특히 경량 서브에이전트마다 필요한 것만 싣기"다. 지금은 모듈을 `.claude/` 파일로 생성해서 레포 단위까지만 고를 수 있고, 생성물은 그 레포의 모든 세션·모든 서브에이전트에 똑같이 실린다. 스폰 규칙은 CLAUDE.md 문장이라 강제되지 않는다.

Claude Code 모드(v2.1.287+)는 세션 안에서 이벤트를 가로채 시스템 프롬프트 섹션, 주입 메시지, 도구 설명, 서브에이전트 생성, 권한 판정을 바꿀 수 있다. 이걸 쓰면 "무엇을 싣는가"를 레포가 아니라 **세션·에이전트 역할** 단위로 정하고, 규칙을 문장이 아니라 코드로 강제할 수 있다.

## 제약 — 모드는 세션 시작 때 한 번 로드된다

세션 도중에 다른 플러그인을 새로 켤 수 없고, 같은 세션의 서브에이전트는 부모와 같은 모드 집합을 쓴다. 그래서 "스폰할 때 모드 조합을 로딩"은 두 갈래다.

| 경우 | 방법 |
| --- | --- |
| 별도 프로세스(`claude -p` 일꾼, crew 작업자) | 실행 인자(`--plugin-dir`, `--settings`)로 조합을 골라 띄운다. child profile 이 컴파일한다 |
| 같은 세션의 서브에이전트 | 이미 로드된 **런타임 모드 하나**가 에이전트별로 동작을 바꾼다 |

## 구조 — 모듈은 데이터, 모드는 런타임 하나

- **모듈 = 선언 데이터.** 규칙(프롬프트 조각), 스폰 규칙(동시 수·모델), 가드(도구·경로·명령), 역할별 도구 목록. 모듈마다 모드를 하나씩 만들지 않는다(디버깅·버전·로딩 순서가 감당 안 된다).
- **harnist-runtime 모드.** 항상 로드되어 레포의 `harness.yaml` 이 고른 모듈 데이터를 읽고 에이전트별로 적용한다.
  - `agent.spawn` — 모델 지정, 동시 수 상한, 금지 역할 거부
  - `prompt.compose` / `prompt.section` — 그 역할에 필요한 규칙만 시스템 프롬프트에
  - `tool.check` / `tool.describe` / `agent.offer` — 역할별 도구·에이전트 목록 거르기
  - `prompt.attachment` — 스킬 목록 주입을 역할별로 줄이기 (원래 문제: 200k 서브에이전트의 스킬 목록 예산 초과)
- **코드 모드.** lens(관측), loop(루프·큐) 처럼 고유 동작이 있는 것만 별도 모드로 두고, 런타임이 데이터로 켠다.
- **그대로 두는 것.** 스킬(필요할 때만 읽힘)과 MCP(외부 연결)는 모드로 옮겨도 이득이 없다.
- **대체 경로.** 조직 관리 환경(프롬프트 계열 이벤트가 사용자 플러그인에 안 옴), VS Code 등 화면이 없는 곳을 위해 지금의 `.claude/` 생성 경로를 남긴다.

## 검증

lens 가 기본 로드 토큰·캐시 히트·턴 점수를 세션마다 기록한다. 같은 레포에서 모드화 전후를 비교하고, lens 의 프롬프트 A/B 실험으로 "규칙을 CLAUDE.md 로 늘 실을 때 vs 런타임이 역할별로 넣을 때"를 세션마다 갈라 비교한다.

## 순서

1. **탐침** — 서브에이전트에 대해 어떤 이벤트가 따로 오는지(시스템 프롬프트 섹션, 스킬 목록 주입, 도구 설명, 에이전트 목록), 각 이벤트가 `agentId` 로 구분되는지 실측한다. 이 결과가 런타임이 할 수 있는 범위를 정한다.
2. **런타임 최소판** — 스폰 규칙 강제와 역할별 규칙 주입.
3. **lens 로 측정** — 전후 비교, A/B.
4. **프로세스 단위 조합** — child profile 에 모드 조합을 얹어 별도 프로세스 일꾼을 목적별로 띄운다.

## 탐침 1 결과 (2026-10-15, Claude Code 2.1.300)

`cc-mods/subagent-probe` 로 sonnet 메인 세션이 Explore(라우터가 haiku 로 보냄)·general-purpose 서브에이전트를 차례로 띄우게 하고 이벤트를 기록했다.

| 이벤트 | 서브에이전트에 따로 오나 | 구분 |
| --- | --- | --- |
| `prompt.compose`, `prompt.section` | **오지 않는다.** 메인 세션에서만 발생 | — |
| `prompt.attachment` | **온다.** 요청마다, 서브에이전트별로 | `agentId` |
| `agent.spawn` | 온다 | 결과에 `agentId` → 종류와 짝지을 수 있다 |
| `turn.start`, `turn.step`, `tool.call` | 온다 | `agentId` |
| `agent.offer`, `tool.describe` | 요청마다 오지만 | `agentId` 없음 → 에이전트별로 거를 수 없다 |

서브에이전트마다 실리는 주입(첫 요청 기준): 스킬 목록 6,931자, MCP 서버 안내 5,949자, CLAUDE.md 5,269자(general-purpose 만, Explore 는 안 받음), 도구 목록·에이전트 목록.

**쓰기 시험**: 서브에이전트의 `skill_listing` 주입만 한 줄로 바꿨더니 서브에이전트는 바뀐 목록만 봤고 메인은 원래 목록 그대로였다. → 런타임은 `agent.spawn` 으로 `agentId → 역할` 을 잡고, `prompt.attachment` 로 그 역할에 맞게 스킬 목록·MCP 안내·CLAUDE.md 를 깎을 수 있다. harnist 의 원래 문제(경량 서브에이전트의 스킬 목록 예산 초과)를 정면으로 푸는 경로다.

**설계에 미치는 영향**
- 서브에이전트 역할별 규칙은 시스템 프롬프트 섹션이 아니라 **주입 메시지 편집**과, 역할 에이전트를 `$.agent.register` 로 정의할 때의 프롬프트로 넣는다.
- 역할별 도구 제한은 설명을 숨기는 대신 `tool.check` 거부로 한다.

## 런타임 최소판 (runtime 0.1.0)

`runtime/` 플러그인. 설정은 레포의 `.claude/harnist-runtime.json`, 없으면 `~/.claude/harnist-runtime.json` (예시: `runtime/examples/harnist-runtime.json`). 역할 키는 서브에이전트 종류, `*` 는 기본값. 메인 세션은 건드리지 않는다.

- `agent.spawn` — 금지 종류 거부, 동시 실행 상한(`$.agent.list()` 의 pending·running·waiting), 역할 모델 지정(Claude 가 고른 모델은 둔다). 결과의 `agentId` 로 역할을 기억한다
- `prompt.attachment` — `skill_listing`(항목 단위), `mcp_instructions_delta`(`## 서버` 절 단위), `deferred_tools_delta`(`mcp__서버__` 줄), `instructions`(`Contents of <경로>` 블록 단위)를 역할대로 거른다. 남는 게 없으면 `null` 로 주입째 뺀다
- `tool.check` — 역할의 `denyTools` 와 열지 않은 MCP 서버 도구를 거부
- `/runtime` — 적용 중인 규칙과 이 세션에서 깎은 글자 수, `/runtime reload`

**실세션 확인** (sonnet 메인, 임시 레포): Explore 는 스킬·MCP 안내·CLAUDE.md 를 하나도 받지 않았고 Bash 가 런타임 사유로 거부됐다. general-purpose 는 허용한 스킬 6개(loop, memory-bank:*)·askew 안내·레포 CLAUDE.md 만 받았고 Bash 는 그대로 됐다. Plan 생성은 런타임 사유로 거부됐다.

**한계**: 처음부터 로드된(지연이 아닌) 도구의 스키마는 `tool.describe` 에 `agentId` 가 없어 숨길 수 없다 — 시험에서 Explore 도 Claude Docs 도구 3개를 봤다. 호출은 `tool.check` 가 막는다. 사용자 범위 router 모드와 모델 지정이 겹치면 먼저 도는 쪽이 정한다.

## 측정 (2026-10-15, lens)

harnist 레포, sonnet 메인이 Explore(haiku)·general-purpose 를 하나씩 띄우는 같은 지시. B 의 설정은 두 역할 모두 스킬·MCP 를 빼고, CLAUDE.md 는 Explore 는 빼고 general-purpose 는 레포 것만 남겼다. 세 번 모두 답은 같았다.

| 실행 | 메인 첫 요청 | Explore 첫 요청 | general-purpose 첫 요청 | 비용 |
| --- | --- | --- | --- | --- |
| A 런타임 없음 (캐시 없음) | 27,341 | 13,128 | 18,959 | $0.186 |
| B 런타임 | 27,343 | **9,413 (−28%)** | **12,400 (−35%)** | $0.081 |
| A2 런타임 없음 (캐시 데워짐) | 27,341 | 13,128 | 18,959 | $0.025 |

- 서브에이전트의 첫 요청 토큰은 캐시와 무관하게 28–35% 줄었다. 서브에이전트의 컨텍스트 여유와, 캐시가 차가울 때의 쓰기 비용이 이득이다.
- **비용은 캐시 상태가 지배한다.** 같은 서브에이전트를 자주 띄우면 깎지 않은 앞부분도 캐시 읽기(10% 가격)로 싸게 재사용된다. B 는 앞부분이 바뀌어 처음 한 번 캐시를 새로 썼다. 그래서 "역할 설정을 자주 바꾸지 않는다"가 운영 규칙이 된다 — 바꿀 때마다 그 역할의 캐시가 한 번 깨진다.
- lens 의 `attachment` 기록에는 `agentId` 가 없어 서브에이전트별 주입 글자 수는 lens 로 못 본다. lens 에 `agentId` 를 붙이는 것이 다음 할 일이다.
